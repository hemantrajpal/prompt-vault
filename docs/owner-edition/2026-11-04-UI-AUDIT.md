# Prompt Vault: application and component audit

Audited on 2026-11-04 at source commit `ca9ad30`. **The core regression suite passes, but the application is not ready for an unrestricted “everything works” sign-off.** During this audit, no application source, stored vault records, deployment or GitHub branch was changed. Recommended “After” states below are not implemented.

## Implementation integrity verdict

**Visual system: coherent. Functional release sign-off: fail until the four P1 issues below are addressed.** The app consistently uses a restrained dark/amber workspace, locally bundled Iconsax, readable summaries and contextual controls. Manual testing nevertheless reproduced uncontained valid category names, obscured keyboard focus, missing field errors and a stale asynchronous category callback that renders the wrong screen.

The Impeccable source detector returned an empty finding array. That is a tool result, not proof of correctness: the reproduced defects below require rendered interaction or state tests.

## Scope, method and limits

- **39/39 existing tests passed**, covering owner authorization, journal/recovery, schema validation, literal prompt assembly, save failure/retry, in-flight prompt locking, category selection/creation, storage, archive/history operations, staged imports/exports, inert markup rendering and pointer/keyboard/reduced-motion dialog behavior. These use fake Google services and Chrome, not a live Google deployment.
- Measured **98 rendered combinations**: library grid, library list, categories, prompt use, editor, settings and category dialog × dark/light × 320, 375, 414, 768, 1024, 1440 and 1920 px. The initial library measurement is an extra capture, for 99 base captures in the JSON.
- Seeded demo content had no measured horizontal overflow in that matrix. A separate valid 80-character category stress case did overflow, so the ordinary matrix must not be read as an edge-case pass.
- Inspected screenshots at 320, 375, 414, 768 and 1440 px; measured computed padding, actual rectangles, effective text/background color pairs and available touch targets. Measurements below use browser rendering, not estimates from CSS alone.
- Keyboard testing used actual Tab and Escape input. Error and delayed-save probes replaced the browser tab's transport temporarily; original state and transport were restored. They made no persistent server writes.
- Chrome viewport emulation is **not physical touch testing**. Physical iOS/Android, Safari/Firefox, assistive-technology speech output, full browser/text zoom, real mobile gestures, live Google identity/scopes, quotas, Sheets persistence and the production deployment remain unverified. A passing computed-color sample is not a full WCAG certification.
- Google Apps Script deployment remains pending the existing app's exact Script ID/editor URL. AI assistance and private image upload remain disabled rather than verified working features.

## Before / After / Why

“After” is a concrete recommendation, not a claim that the code has been changed.

| Before | After | Why |
| --- | --- | --- |
| Text inputs 46 px on mobile, buttons/selects 44 px; segmented wrapper 50 px | One explicit 44 px desktop control size and a consistent 48 px touch variant, including the whole segmented group | Eliminate small alignment differences and improve touch comfort |
| Editor labels have 8 px gaps, dialog labels have 16 px | Share one 8 px label gap; remove dialog label margins | Consistent form rhythm |
| Save is left in the dialog body; Close is right in a separate footer | One action footer with primary Save and secondary Cancel/Close, 8 px gap | Shorter scan path and clearer hierarchy |
| Badge text sits inside a 14 px high label with no vertical padding | A named compact badge style, around 18 px high, 11 px type and 2 / 6 px padding | Keep secondary metadata readable without competing with titles |
| “Export current prompts & categories” wraps at 320 px | Short visible label such as “Export prompts & categories” | Preserve one-line button rhythm |
| Long category names are unconstrained in heading, sidebar and filter | Wrap the heading safely; constrain and truncate navigation/filter labels while preserving the full accessible name | Valid content must not break the viewport |
| Modal Save is disabled but Close/navigation can outlive its callback | Scope the request to the originating view, guard stale callbacks and show a clear pending state | Avoid rendering a discarded editor after navigation |
| Save error says “highlighted fields” but shows no field error | Render server field messages by their fields with `aria-invalid`, `aria-describedby` and focus to the first error | Make recovery possible without guessing |

## Prioritized findings

### P1 — fix before release

**F01 · Valid long category names break layout.**

- **Location:** [_Styles.html:18](../../src//_Styles.html#L18), [_Styles.html:44](../../src//_Styles.html#L44), [_Styles.html:65](../../src//_Styles.html#L65); category labels originate at [_Scripts.html:40](../../src//_Scripts.html#L40) and [_Scripts.html:59](../../src//_Scripts.html#L59).
- **Evidence:** a valid 80-character unbroken category name was accepted by the isolated backend validator. At 320 px the category filter became **662.4 px wide** and the heading's scrollable content was **1188 px** wide. The name paints behind/through the primary action and extends past the viewport. [Screenshot](audit-evidence/2026-11-04/vault-audit-long-category.png) · [Probe result](audit-evidence/2026-11-04/vault-audit-edge-results.json).
- **Impact:** valid user data makes navigation and the page title unreadable. Category names with spaces can also wrap sidebar labels at 768 px.
- **Category/standard:** Responsive; WCAG 1.4.10 reflow risk.
- **Recommendation:** constrain the label flex item (`min-width:0`, a maximum inline size), safely wrap the heading and give navigation labels an intentional single-line truncation/full-name affordance. Test all 80-character category names, not only short seeds.
- **Suggested command:** `$impeccable harden`, then `$impeccable adapt`.

**F02 · Focus moves behind the open mobile drawer.**

- **Location:** [_Scripts.html:189](../../src//_Scripts.html#L189) and [_Scripts.html:202](../../src//_Scripts.html#L202).
- **Reproduction:** at 320 px, open navigation, focus the theme button near the end of the sidebar, then press Tab. Focus moves to `#mobile-menu-btn` behind the open drawer. `#main.inert` remains false. Escape closes the drawer without a general focus-return path; only the explicit Close button restores focus.
- **Impact:** keyboard users can interact with obscured background controls.
- **Category/standard:** Accessibility; WCAG 2.4.11 focus not obscured and focus-order concerns.
- **Recommendation:** make the background inert while the modal drawer is open, contain Tab/Shift+Tab and restore focus to the opener for every dismissal route, including Escape and backdrop.
- **Suggested command:** `$impeccable harden`.

**F03 · Server field errors are discarded by the prompt editor.**

- **Location:** [_Scripts.html:134](../../src//_Scripts.html#L134), [_UI.html:18](../../src//_UI.html#L18); the server already supplies field keys/messages in [Auth.gs:25](../../src//Auth.gs#L25).
- **Evidence:** a controlled `VALIDATION` response with `fieldErrors.tags = "Use at most 20 tags."` produces only “Review the highlighted fields.” The DOM has **zero** `aria-invalid=true` fields and never renders the detailed message. The draft is retained. The global error also persists after leaving the editor. [Probe result](audit-evidence/2026-11-04/vault-audit-edge-results.json).
- **Impact:** the user cannot identify or correct the invalid value despite the interface claiming it highlighted it.
- **Category/standard:** Accessibility and error recovery; WCAG 3.3.1/3.3.3.
- **Recommendation:** map field errors to the actual control or variable group, render associated help/error text, focus the first invalid control and clear stale route-level errors on navigation. Keep the existing draft-preservation behavior.
- **Suggested command:** `$impeccable harden`, `$impeccable clarify`.

**F04 · A delayed category save can render the editor over Settings.**

- **Location:** editor callback at [_Scripts.html:107](../../src//_Scripts.html#L107); modal save at [_Scripts.html:148](../../src//_Scripts.html#L148).
- **Reproduction:** add a category from the editor, delay its response, close the dialog and navigate to Settings, then resolve the response. The probe ends with `page === "settings"`, **editorVisible = true**, **settingsVisible = false**, **dirty = true**. Save is disabled while pending, but Close remains enabled and `requestState` stays `ready`.
- **Impact:** the visible page, selected navigation and application state disagree; a discarded authoring context reappears unexpectedly.
- **Evidence:** [Delayed-save result](audit-evidence/2026-11-04/vault-audit-category-race.json). This was a controlled browser-transport response, not a production save or proof of persisted data loss.
- **Recommendation:** capture a view/draft generation ID, ignore stale view callbacks and decouple refreshing committed category data from reopening the originating form. Decide explicitly whether closing cancels only the view or the pending action.
- **Suggested command:** `$impeccable harden`.

### P2 — correct in the next component pass

**F05 · The control-size system changes across component types and breakpoints.**

- **Location:** [_Styles.html:38](../../src//_Styles.html#L38), [_Styles.html:39](../../src//_Styles.html#L39), [_Styles.html:44](../../src//_Styles.html#L44), [_Styles.html:53](../../src//_Styles.html#L53), [_Styles.html:54](../../src//_Styles.html#L54), [_Styles.html:65](../../src//_Styles.html#L65).
- **Evidence:** the measured geometry table above. The segmented group is 46/50 px tall alongside a 44 px search; mobile text inputs are 46 px while selects/buttons remain 44; the notes disclosure is only 24 px. A 320 px export button becomes 58.4 px high and the 768 px “Brand & discovery” navigation label wraps.
- **Impact:** the app feels uneven despite shared border radii and colors. Several controls miss UI/UX Pro Max's 44 px comfort target; 36/40 px controls do **not automatically violate** WCAG's 24 px AA minimum.
- **Recommendation:** shared control-height, field-padding and action-gap tokens; explicit compact variants only where justified. Keep icon glyph size independent from target size. Shorten long static action labels and constrain variable navigation labels.
- **Suggested command:** `$impeccable extract`, `$impeccable adapt`, then `$impeccable polish`.

**F06 · Dialog label spacing and action placement diverge from the editor.**

- **Location:** [_Styles.html:54](../../src//_Styles.html#L54), [_Styles.html:57](../../src//_Styles.html#L57), [_Scripts.html:148](../../src//_Scripts.html#L148), [_UI.html:33](../../src//_UI.html#L33).
- **Evidence:** rendered gap **16 px** in all three category-dialog fields versus **8 px** in the editor. Save sits left in form content and Close right below a rule. [Dialog screenshot](audit-evidence/2026-11-04/vault-audit-dialog-desktop.png).
- **Impact:** unnecessary height and two separate decision/action areas make an otherwise short form feel clunky.
- **Recommendation:** remove extra label margins, reserve a bounded inline error region and put related actions in a single footer.
- **Suggested command:** `$impeccable layout`, `$impeccable polish`.

**F07 · Archived categories have no recovery path in the interface.**

- **Location:** [_Scripts.html:151](../../src//_Scripts.html#L151), [_Scripts.html:142](../../src//_Scripts.html#L142), [Sheets.gs:35](../../src//Sheets.gs#L35).
- **Evidence:** the category view shows only active categories. The archive view contains prompts, not category recovery controls. The backend can save an existing category's status, but no UI exposes restoring an archived category. If the last active category is archived, Restore shows no destination buttons until the user separately creates a new category.
- **Impact:** the user can recover prompts by recreating a destination, but cannot directly restore the original category organization through the app.
- **Recommendation:** expose archived-category recovery or clearly guide the user to create/select an active destination. Test the “all categories archived” state explicitly.
- **Suggested command:** `$impeccable harden`, `$impeccable onboard`.

**F08 · Empty Archive uses the first-run library message.**

- **Location:** [_Scripts.html:65](../../src//_Scripts.html#L65).
- **Evidence:** with zero records, Archive says “Your vault starts here” and offers Create prompt; with active records but no archived results it says “No matching prompts.” Both miss the actual empty-archive state. [Probe result](audit-evidence/2026-11-04/vault-audit-edge-results.json).
- **Impact:** the page suggests the vault is empty even when the archive is simply unused.
- **Recommendation:** “Your archive is empty” with a Back to prompts action; distinguish unfiltered emptiness from filtered no-results.
- **Suggested command:** `$impeccable onboard`, `$impeccable clarify`.

**F09 · Full-library redraw becomes a long task near the supported limit.**

- **Location:** [_Scripts.html:49](../../src//_Scripts.html#L49), [_Scripts.html:201](../../src//_Scripts.html#L201).
- **Evidence:** local synchronous render plus forced layout for 6/100/500 synthetic records: about **1.4–1.9 / 19.4–23.1 / 82.3–85.3 ms**. At **4× CPU slowdown**, 500 records took **322.5–352.3 ms**. Three samples per count; no network latency included. Temporary browser records were restored afterward. [Normal CPU](audit-evidence/2026-11-04/vault-audit-performance.json) · [4× CPU slowdown](audit-evidence/2026-11-04/vault-audit-performance-4x.json).
- **Impact:** clearing search or changing layout/category at the 500-prompt cap can briefly block input on slower devices.
- **Recommendation:** paginate or incrementally render visible records, reduce repeated category counts and avoid rebuilding unrelated controls for every search. Measure again at 500 before choosing heavier virtualization.
- **Suggested command:** `$impeccable optimize`.

### P3 — keep polish focused

**F10 · The closed mobile drawer still casts a shadow into the page.**

- **Location:** [_Styles.html:65](../../src//_Styles.html#L65).
- **Evidence:** the box-shadow is present on the closed, translated sidebar, leaving a gray vertical veil on the left of the light Settings screen. [Light mobile screenshot](audit-evidence/2026-11-04/vault-audit-414-settings.png).
- **Impact:** it suggests a partially dismissed overlay even though navigation is closed.
- **Recommendation:** apply the shadow only in `.open`, or hide the closed drawer's shadow while preserving its transition.
- **Suggested command:** `$impeccable polish`.

**F11 · Compact labels and spacing lack a durable token vocabulary.**

- **Location:** [_Styles.html:16](../../src//_Styles.html#L16), [_Styles.html:44](../../src//_Styles.html#L44), [_Styles.html:48](../../src//_Styles.html#L48), [_Styles.html:49](../../src//_Styles.html#L49), [_Styles.html:57](../../src//_Styles.html#L57).
- **Evidence:** count labels are 14 px tall with zero vertical padding; raw shadow values and literal font declarations sit outside tokens; gaps/margins include repeated 7/9/10/14/18 px special cases. This is maintainability/taste drift, not a contrast failure.
- **Impact:** future refinements are likely to repeat the current padding mismatch.
- **Recommendation:** define semantic field, button, badge, panel and shadow tokens. Keep small optical offsets explicit; do not force every glyph adjustment onto a grid.
- **Suggested command:** `$impeccable extract`, `$impeccable document`, `$impeccable polish`.

## Creative direction and Hallmark review

**Overall impression:** the app reads as a focused workspace, but shared controls still look tuned individually rather than governed by one component system. Another broad visual replacement is not the first remedy; fix geometry, modal actions and state correctness first.

**Working:** restrained warm accent, high-contrast dark surfaces, readable summaries, calm action hierarchy and a consistent Iconsax stroke voice. Clear Use/Edit access survives grid and list. No invented business claims, fake browser chrome, generic stock imagery or ornamental page-load choreography were found.

**Not working:** the library's calm spacing does not consistently carry into dialogs and settings. The real problems are visible in measured heights, label gaps, wrapped control labels and a closed-drawer shadow.

**Hierarchy:** New prompt is the library's dominant action; the editor correctly promotes Save. The modal weakens this by splitting Save and Close. Error hierarchy is inadequate because the actionable detail is discarded.

**Emotional fit:** the dark/amber direction suits Hemant's profile while preserving the clarity an operational tool needs. The light theme remains a user preference; there is no reason to remove it to make every surface cinematic.

**Actionable order:** fix F01–F04, normalize controls and dialog rhythm (F05–F06), finish archive recovery/empty states, then optimize and polish.

Hallmark named anti-patterns:

| Severity | Tell | Where | Concrete correction |
| --- | --- | --- | --- |
| Major | Wrap-to-two-lines clickable text | Export at 320 px; sidebar category at 768 px; F05 | Shorten static action copy and constrain variable nav labels |
| Major | Mid-render token improvisation | Literal fonts and shadow colors outside the palette block; F11 | Lift reusable values into named semantic tokens |
| Minor | Off-scale spacing (gate 24) | Repeated unlabelled gaps/padding in F05/F06/F11 | Establish component spacing tokens and document optical exceptions |

**Named anti-pattern tally: 0 critical · 2 major · 1 minor.** Technical layout/focus/state defects are separately prioritized above. This is **not** a 58/58 pass: layout-safety, input-state, spacing and token gates remain open.

Contextual exceptions and false-positive prevention:

- Hallmark's Inter-everywhere rule conflicts with Impeccable's explicit Operate guidance that one well-tuned sans is often right. This app deliberately uses a single UI family. Adding a display face would not fix the measured defects.
- Three equal columns contain real prompt records, not generic icon/feature marketing tiles. Breaking their proportions for novelty would reduce scanability.
- Native checkboxes use full associated labels as targets. Their 18 px glyph alone is not evidence of a tiny hit target.
- Normal prompt titles are content and may wrap. The one-line action-label rule should not truncate meaningful prompt titles.
- Text/background checks excluded disabled controls. No claim is made that enabled-control contrast measurements prove every icon, border, gradient or transient animation frame compliant.
- Confirmation before archiving multiple records remains a reasonable safeguard until equivalent Undo/recovery behavior is reliable; replacing it merely to satisfy a stylistic preference would be premature.

## What passed and should be preserved

- Every sampled enabled label/control text pair in the ordinary matrix passed **4.5:1**, using effective painted background colors. Example dark button contrast: **8.73:1**; muted card text: **6.88:1**. Transparent-control backgrounds were resolved through ancestors.
- Visible 2 px focus outlines; correctly associated form labels; explicit required indicators; live status/error announcements; inert collapsed sidebar; native modal dialogs.
- Pointer press feedback is 120 ms at scale .975. Dialog entry is 180 ms and exit 120 ms, using transform/opacity and a custom ease-out curve. Keyboard and reduced-motion dialog interactions are instant. The existing motion regression verifies the real WAAPI calls.
- Hover styling is gated to fine pointers; filters and search do not wait for a decorative entrance.
- Prompt save failures retain the draft; the prompt save operation locks controls while its acknowledgment is pending. The separate category-save defect must not regress this stronger prompt-save path.
- Literal substitution, schema validation, expected revisions, operation IDs and checksummed backup flows have regression coverage. No raw stored text was rendered as executable markup in the relevant test.
- The base runtime is lean and has no added animation/icon library dependency. Browser console reported no errors during ordinary and controlled edge-case probes.

## Recommended execution order

1. **P1 `$impeccable harden`**: stale category callbacks, field-level validation, mobile drawer focus and long category data.
2. **P2 `$impeccable adapt` / `$impeccable layout`**: shared control geometry, label gaps, modal action alignment and long static labels.
3. **P2 `$impeccable onboard` / `$impeccable clarify`**: archived-category destination guidance and correct empty archive copy.
4. **P2 `$impeccable optimize`**: bounded rendering at 500 prompts.
5. **P3 `$impeccable extract` / `$impeccable document`**: component tokens and documentation grounded in the shipped app; offer init separately for durable product context.
6. **`$impeccable polish`**: final rendered check, including the closed-drawer shadow; rerun the audit and add regressions for F01–F04.

These commands can be run individually or together. Re-run `$impeccable audit` after fixes to reassess the score.
